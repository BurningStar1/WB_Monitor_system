## 1. ТЕМА И ЦЕЛЬ

**Тема:** Разработка аналитического сервиса формирования интерактивных отчётов для мониторинга продаж на маркетплейсе

**Цель:** Повышение эффективности анализа продаж путём разработки аналитического сервиса формирования интерактивных отчётов на основе витрины данных для мониторинга продаж на маркетплейсе.

**Объект:** Процесс аналитической обработки данных о продажах на маркетплейсе «Wildberries»

**Предмет:** Методы и технологии формирования витрины данных и построения интерактивных отчётов для анализа показателей продаж в электронной коммерции

## 4. АРХИТЕКТУРА СИСТЕМЫ

### 4.1 Слои хранения данных
- **RAW** — исходные JSON-ответы WB API, хранятся без изменений (`raw.wb_api_payloads`, поле `raw_payload JSONB`)
- **STG** — очищенные и нормализованные данные (`stg.wb_orders`, `stg.wb_sales`, `stg.wb_stocks`)
- **DICT** — справочники продавца (`dict.cost_reference`, `dict.extra_expenses`, `dict.tax_reference`)
- **MART** — витринный слой: `mart.orders_daily`, `mart.sales_daily`, `mart.stocks_snapshot`, `mart.ads_daily` + 11 views
- **APP** — пользователи и аккаунты WB (`app.users`, `app.wb_accounts`, `app.user_accounts`)

### 4.2 Модули системы
| Модуль | Назначение |
|---|---|
| Коннектор WB API | Получение данных из Statistics API (orders, sales, stocks) |
| Загрузка внутренних данных | Чтение XLSX-справочников (себестоимость, расходы, налоги) |
| Управляющий модуль | Оркестрация pipeline: запуск, расписание, контроль |
| Модуль подготовки данных | Очистка, нормализация, дедупликация → STG |
| Модуль формирования витрин | Агрегирование STG → MART |
| Аналитический модуль | Расчёт KPI, ABC-анализ, прогноз заказов |
| Модуль интерактивной отчётности | Streamlit-интерфейс с фильтрами и графиками |
| Модуль журналирования | Логи выполнения, фиксация ошибок |

### 4.3 WB API эндпоинты (Statistics API)
- `GET /api/v1/supplier/orders` — заказы
- `GET /api/v1/supplier/sales` — продажи и возвраты (saleID: 'S...' = продажа, 'R...' = возврат)
- `GET /api/v1/supplier/stocks` — остатки
- Пагинация через `lastChangeDate` в параметре `dateFrom`, `flag=1`
- Данные обновляются каждые 30 минут
- Лимит: 1 запрос в минуту на каждый эндпоинт

## 5. МАТЕМАТИЧЕСКИЙ АППАРАТ

```
Выручка:       R = Σ(p_i × q_i)
Прибыль:       P = R − C_wb − COGS
Опер. прибыль: OP = P − E − τ
Маржинальность: M = P / R
Рентабельность: ROI = P / (COGS + C_wb)

ABC-анализ: ранжирование по убыванию v_i, накопленная доля F_k = Σ(d_i), i=1..k
  A: F_k ≤ 0.80, B: 0.80 < F_k ≤ 0.95, C: F_k > 0.95

Прогноз заказов (скользящая средняя):
  Q̂_{t+1} = (1/n) × Σ Q_{t-i+1}, i=1..n
```

Где: `C_wb` — комиссии и удержания WB, `COGS` — себестоимость, `E` — доп. расходы, `τ` — налог

## 6. ОТЧЁТЫ (по скринам конкурентов — ориентир для разработки)

### 6.1 Общий дашборд
**Фильтры:** Тип отчёта, Компании (мультивыбор кабинетов), Период

**KPI-карточки верхнего ряда:**
- Реализация = Продажи − Возвраты; показывает вклад продаж и возвратов
- Услуги = Комиссия + Логистика + Реклама + Остальные (с % от реализации)
- Налоги и затраты = Налог + НДС + Себестоимость продаж + Затраты (с %)
- Операционная прибыль + Маржинальность % + Рентабельность %

**KPI-карточки нижнего ряда (за день):**
Заказы / Продажи / Логистика / Реклама / Все услуги — с мини-графиком динамики и % изменением к предыдущему дню

**График:** Динамика показателей по дням (заказы + продажи + прибыль, сгруппированные столбцы)

### 6.2 Отчёт по артикулам
**Фильтры:** Тип отчёта, Компании, Артикул поставщика, Предмет

**Таблица:** Фото | Предмет | Артикул поставщика | Остаток | Динамика остатков (мини-график) | Заказы (сумма) | Скорость заказов (ср. в день) | Заказы по дням (последние 7 дней) | Динамика заказов (мини-бар) | % выкупа | Цена до СПП | Цена после СПП | СПП % | Комиссия | Логистика | Реклама | Доля рекламных расходов %

### 6.3 Рука на Пульсе (РНП) — ключевой ежедневный отчёт
**Фильтры:** Тип отчёта, Компании, Период, дополнительные Фильтры

**Тоглы:** Метрики / Процентное изменение / Тепловая карта

**Таблица:** Товар (фото + nmId + артикул + схема FBO/FBS) | Заказы (шт) | Реализация до СПП | Реклама (баланс+счёт) | Прибыль

**Строка "Сводные данные"** — суммы по всем позициям

*Примечание: в архиве WinRAR есть дополнительные скрины других отчётов — Excel-отчёты. Их нужно рассмотреть отдельно.*

## 10. ПРЕДМЕТНАЯ ОБЛАСТЬ — КОНТЕКСТ

Wildberries — маркетплейс. Продавец работает по схеме FBO (хранение на складе WB). Ключевые понятия:
- **nmId** — идентификатор товара в системе WB
- **supplierArticle** — артикул поставщика
- **srid** — уникальный идентификатор заказа
- **saleID** — идентификатор операции (S... = продажа, R... = возврат)
- **СПП** — скидка постоянного покупателя (влияет на цену для покупателя)
- **Реализация** = Продажи − Возвраты (в рублях)
- **Комиссия WB** — процент от реализации, удерживаемый платформой
- **Логистика** — расходы на доставку до покупателя и обратно при возврате
- **Себестоимость** — внутренние данные продавца, загружаются из XLSX
- Данные продавца: 2 кабинета (компании), товарная группа — светильники/бра/люстры
